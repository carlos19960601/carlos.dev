从 Figma 到代码：组件 API 的取舍

2026.02 · 约 6 分钟 · Carlos

一个按钮组件，设计稿里画了 12 个变体，到代码里我只暴露了 4 个 props。这篇聊聊这中间的取舍。

设计稿的「全」和代码的「简」

设计稿的工作是覆盖所有可能，所以 12 个变体是合理的：它要把每种状态、每种尺寸、每种语义都演示一遍。但代码的工作相反，是约束滥用。那 12 个变体里，有一半其实是为了「以防万一」而存在的。

把「以防万一」照搬进 API，团队很快就会出现十几种谁也不敢删的配置组合。

四个 props 是怎么选的

最后留下的是 variant、size、tone、disabled。每一个都对应一类真实且高频的需求。剩下那些「偶尔要」的差异，交给 token 在外层覆盖，不进组件 API。

好的组件 API，是让错误的使用方式变得别扭。

取舍的标准不是「能配置多少」，而是「让正确的事变得容易」。少几个 props，多几分纪律。
